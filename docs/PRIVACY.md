## Purpose and access

MediaLatch processes page content and media addresses to identify the selected source, save accessible media and provide save feedback. Content scripts inspect selected targets, their owning post/player and relevant page metadata. Shared inline Save controls run on the tested X/Twitter, Reddit, Pixiv, RedGIFs and VK surfaces in the top frame. TikTok and Instagram Reels have separate selected-player Copy/Download controls; Instagram ordinary posts retain their existing Copy controls. vkvideo.ru uses a VK handler for browser-menu saves, Copy link and Download on supported video cards/clips, and Download on the proven player of an opened page, whether its source is unresolved, a blob or a direct MP4. Other sites use the browser context menu; generic inline controls are disabled. They inspect the hovered or focused media and nearby post structures locally; hovering makes no network request. This access is needed on HTTP/HTTPS sites and in relevant frames.

The extension has no analytics, advertising, telemetry endpoint or developer-operated media server. It does not upload save history or diagnostic reports automatically. It does not sell user data.

## Network requests

Resolving and downloading media contacts the source site, its declared CDN and, where supported, provider metadata APIs. Requests can include normal browser credentials where the existing provider path requires them. For an admitted Pixiv save, artwork metadata can supply its author name and user ID for the author label and optional folder name. Matched Danbooru/Moebooru post metadata can supply uploader naming and publication time for filenames and opted-in folder templates; artist tags do not become account identity. Other account labels are read locally from the selected post itself (see "Posting-account metadata" below); they cause no extra request. The receiving service can observe the request address, IP and normal network metadata under its own policies.

An admitted VK Video menu save can request first-party video metadata from the selected vkvideo.ru document at /al_video.php, using that document’s same-origin session. The metadata must match the selected video; the declared progressive file is fetched from its admitted CDN. For a VK clip, the extension asks the page's own client for the clip's download address in the same document (the page's session; only the address or an error code comes back). Hovering a video card makes no network request. The optional diagnostic journal records only numbers for the phases of a save (API wait, wait for headers and first byte, body, validation, export); no credentials or signed source addresses are added to shared diagnostics.

The RedGIFs path can request a temporary guest token from the provider for an admitted save. That token stays in the frame's lookup and is not returned as feedback, retained as history or logged.

Opening Updates can contact GitHub's public releases API at most daily; an explicit check bypasses the daily cache. The request omits credentials and referrer. It checks versions and links to a fixed repository; it does not execute remote code or install an update. The latest release notes are bundled with the extension in English/Russian and need no request to read offline.

Copy-link settings may produce links to third-party preview services. Copying such a link does not itself request that service. Opening or sharing it is a separate user action. Site-bound Copy controls also cover YouTube videos/Shorts, Bluesky, Threads, Tumblr, Twitch clips and Bilibili, alongside X, Instagram, TikTok, Reddit and Pixiv. They read the owning post/video address locally; a Copy-only integration does not add a media-download adapter.

## Local storage

- **Preferences and release-check cache:** local browser extension storage, until changed or the extension's data is removed. Preferences include the optional interface language (`en` or `ru`); when no language choice is saved, the browser's language setting is used instead, and neither is sent anywhere. The first-run welcome also keeps one boolean marker (`firstRunGuideDismissed`) in local extension storage, written only when you press Continue on the install welcome and read from that storage only.
- **Recent save feedback:** a bounded validated posting-account identity (X, Reddit, Pixiv, VK, RedGIFs, Instagram or TikTok) can be retained and displayed with the result. Session storage, targeting 20 recent operations and a 24-hour retention window for finished operations. Active operations are retained while pending and can exceed that count. Browser session storage clears when the browser session ends.
- **Optional statistics:** off by default, preserving the previous recording preference. Private extension IndexedDB holds aggregate outcomes, output types and measured byte totals, both overall and by a finite supported-service category, plus compact per-operation contributions for duplicate prevention. There is no entry/time retention limit; browser storage capacity still applies. Statistics do not retain media addresses, filenames or paths. Per-site categories describe saved operations, not general browsing history; unknown old counts remain unattributed. Booru grouping and the selected filter are display-only. Available legacy history is imported once; already removed entries cannot be recovered. Legacy history metadata from older versions remains in local storage for compatibility; new saves do not append to it.
- **Optional Debug journal:** recording is off by default. Local extension storage retains at most 2,000 events, 1 MiB and 24 hours. Events include allowlisted action/error codes, timestamps, numerical/boolean details, hosts and validated post/media/job identifiers for correlating extension actions. Full URLs, queries, tokens, cookies, headers, raw errors/stacks, page or React data, page text, filenames, folders, local paths and clipboard contents are excluded. Turning recording off preserves the existing journal; Clear removes it. Retention is enforced when the journal is accessed or updated.
- **Optional local thumbnails:** supported completed saves can retain a static WebP preview in private extension IndexedDB, bounded to 2,048 entries in 3.0.2 (128 in 3.0.1), and 22,000 characters per WebP data URL (images at most 128px). Previews come from already admitted local bytes, with no extra media request; busy/unsupported/slow/evicted files keep type icons. Removing a job removes its preview. These images are not statistics, Debug events or exported diagnostic reports. When successful source-page notices are enabled, the worker can send a tiny owned-cache copy for the exact completed operation to its original tab, origin and top frame. The notice uses a 40px decorative preview and a type-icon fallback. This displays the copy in that source page's notice, not on an unrelated page or a developer server.
- **Active work:** memory and session bookkeeping can hold job/download IDs and local blob handles for lifecycle recovery. Media source URLs and binary data are processed as needed for an active save; the browser's own downloads system also maintains its normal download records.
- **Download manager:** private extension IndexedDB retains job state, intended/actual filenames, output size/type and owned browser download IDs, plus a normalized owning-service token for retry attribution. Jobs and post batches can also retain the validated posting-account name/username and ID (same seven services) for labels and retries. Post-batch metadata contains a bounded group ID/service, item states and associated operation/job IDs; an optional Pawchive partial-import flag contains no missing-file count or post URL. Pending or failed jobs also retain their exact source URLs, including signed queries, for explicit retry; these are not placed in shared extension storage, Debug events or reports. The extension's private disk storage (OPFS) holds received bytes until validation and browser export finish. Completed/cancelled jobs attempt to delete temporary bytes and source/local-blob URLs. A cleanup failure can retain temporary bytes and private source/prepared metadata until later cleanup or explicit removal; cleanup is not a guaranteed immediate deletion. Failed exports retain prepared bytes until retry or record removal. Removing a manager record does not delete your exported file. Records have no automatic time/count expiry; storage quota applies. Browser restart reconciles owned exports; interrupted acquisition is not silently resumed.

**Since 3.0.2:** Overview → Local data and backups exports separate JSON copies for statistics and terminal history. Statistics restore explicitly replaces aggregate counters, preserves the recording preference and fences operations started before restoration; active work refuses restore. History copies contain record IDs, basenames, site/account labels, timestamps, outcomes and byte totals. Import adds missing metadata-only rows without fetch/retry, statistics updates or filesystem authority. Media, thumbnails, source/post URLs, signed queries, headers, native download IDs, folder handles/receipts and active jobs are excluded. Keep history copies private. UTF-8 size and record bounds are in the table above. Invalid input or failed transactions keep prior data. No automatic external config is written. See [local data](LOCAL_DATA.md).

Statistics has global recording and Clear statistics controls. The selected site filter does not limit clearing: it clears every site, including hidden/legacy buckets. Turning recording off preserves totals. Clear statistics removes its counters and duplicate-prevention ledger; pre-clear operations cannot restore them. It does not remove legacy history metadata or downloaded files. Removing extension storage/uninstalling removes extension-local data; browser downloads and saved files are managed separately.

Selecting a base folder grants local write access only after a browser picker action. Private extension IndexedDB retains directory handles and per-file export receipts (destination ID, relative filename, type, size and job/operation identifiers). Receipts are removed with the manager record; previously selected handles remain until extension data is cleared. Handles and destination paths never enter Debug reports. Direct writes do not create Chrome download-history entries. Optional author folders use the posting account of the selected media locally to build the folder name. If the account cannot be determined, the normal folder layout is used. The metadata is not sent to the developer.

### Posting-account metadata

Author labels and optional author folders name the account that posted the selected media, not the original artist. The identity is accepted only in a validated shape per service and only from the selected media's own post: X and Reddit use the selected post's username; Pixiv uses artwork metadata (name and numeric user ID); VK uses the account linked in the post header; RedGIFs uses the user linked on the same player card; Instagram ordinary attachments use the post header account of a post with one permalink. For TikTok videos and Instagram Reels, the same document-pinned player-item read that identifies the requested file also provides its posting username (TikTok author string/uniqueId or Instagram item.user.username); it does not borrow a neighbouring profile or a display name. An account is given only with positive evidence that the selected media is the post's own attachment: on TikTok and RedGIFs it must be the post's one video; on Instagram the part of the post holding it must name no other person or account; VK keeps its selected-post checks. Media in a header (the avatar), media inside a link to an account page and media in a comment, reply, quote or nested card that the page marks as such (with or without a profile link) get no account. Missing or ambiguous evidence leaves the account unknown and uses the normal folder layout; the media is still saved. Equal names on different services are different accounts. This metadata is retained and displayed independently of whether author folders are enabled.


## Reports and diagnostics

MediaLatch uses notices on the source web page instead of desktop notifications. Batch notices use the same committed counts as the manager; partial-import diagnostics remain separate from the file totals. They show bounded site/type/result text and, when proven, the posting-account label, without filenames, paths or source URLs, in a closed Shadow DOM. Delivery is limited to the original tab and origin. Session feedback holds a tab ID and origin for delivery/restart; legacy history, reports and Statistics exclude this route. Closing/navigating the tab or a restricted page can prevent a notice; the manager and failure badge remain. Page notices are UI inside the website, not a confidential system surface. The older v2.0.0.28 preview uses its original notification mechanism.

Bug reports are created and copied only when requested. The report builder allows bounded fields and removes addresses, paths and token-bearing data from its structured output. Diagnostic log copies redact known signed query parameters; the exact request URL is preserved for the actual transfer.

Review any text you choose to paste or share. Browser/developer logs and screenshots can contain context outside the generated report. The extension does not submit the report itself.

Debug events can be filtered, copied or exported only by user action. Exports contain the selected sanitized events and extension/report metadata; hosts and post/media identifiers can still reveal which media was involved. The extension does not upload these exports or send Debug events to the developer.

## Limited use

MediaLatch uses the data described here only to provide its media-saving, organization, feedback and optional diagnostics features. It does not use the data for advertising, sell it, or transmit history/diagnostic exports to the developer automatically. Network transfers are limited to the source/provider service needed by the requested save, explicit user sharing/copy/export, and the described GitHub release-version check.

## Changes

Future features that change storage or network behavior must update this policy. Browser store disclosures must describe the actual submitted build, including local processing; this file does not replace the store's required form.


Full image, animated GIF and MP4 previews use exact staged media bytes in a disposable private IndexedDB cache (the build-specific bounds above). Cache eviction or failure never changes an export receipt or saved file. Removing a managed job removes its cached original; startup prunes missing jobs and expired cache entries. Expiry is checked on reads; physical pruning also runs on writes/startup, not while the browser is closed. Chosen-directory previews read the exact collision-adjusted receipt path through its existing granted handle. No original is sent to a website or refetched from a CDN. Older/evicted originals may be selected explicitly from disk in the themed viewer. Preview Blob URLs are page-local and revoked on close.

Popup and on-page toast thumbnails open the same themed viewer over the active/owning website, in a closed Shadow DOM containing an extension-origin frame. A bounded session in extension-private chrome.storage.session survives worker restarts and binds its token to the tab, origin and frame document; original bytes and disk paths never cross into website JavaScript. Popup closes after viewer readiness. Restricted pages or blocked frames fall back to Download Manager with that viewer already open. The viewer supports fit/100%, wheel zoom, pan, previous/next retained media, Escape/backdrop close, focus restoration and reduced motion. A direct close message from the owned frame also removes the overlay after a worker restart. No browser window is created.

Optional publication-date filename tokens use proven X post timestamps or matching Danbooru/Moebooru post metadata, in UTC. Unknown publication dates are omitted; download time is never substituted. Original-name mode retains the basename; metadata-based naming uses only the selected known fields and omits the CDN basename. These preferences name new exports and do not rename existing disk files. Clearing statistics or manager records does not authorize overwriting a colliding disk file.
