## ⚡ О проекте

**MediaLatch** сохраняет выбранные изображения, видео и GIF со страницы. Меню браузера и кнопки на поддерживаемых сайтах запускают скачивание, менеджер показывает результат каждого файла, а встроенный просмотрщик открывает сохранённое медиа.

Папки, имена новых файлов, уведомления и статистика настраиваются. Дополнительная программа не нужна; собственного сервера и телеметрии у расширения нет.

## 🚀 Установка и обновления

<p align="center"><img src="assets/readme/install-ru.svg?v=violet-loop-zip-3" width="1120" alt="ZIP и CRX: Releases, SHA-256 и правила установки браузера"></p>

Скачайте **[ZIP 3.0.5](https://github.com/xhthc/MediaLatch/releases/download/v3.0.5/MediaLatch-3.0.5.zip)** для загрузки распакованного расширения или [CRX 3.0.5](https://github.com/xhthc/MediaLatch/releases/download/v3.0.5/MediaLatch-3.0.5.crx) для разрешённых браузером способов установки. Для каждого формата есть своя сумма: [ZIP SHA-256](https://github.com/xhthc/MediaLatch/releases/download/v3.0.5/MediaLatch-3.0.5.zip.sha256), [CRX SHA-256](https://github.com/xhthc/MediaLatch/releases/download/v3.0.5/MediaLatch-3.0.5.crx.sha256). [Состав сборки](https://github.com/xhthc/MediaLatch/releases/download/v3.0.5/MediaLatch-3.0.5.provenance.json) описывает одинаковые 104 файла обоих пакетов. [Все выпуски](https://github.com/xhthc/MediaLatch/releases).

Для Chrome используйте [страницу MediaLatch в Chrome Web Store](https://chromewebstore.google.com/detail/medialatch/cimghidldpjhhhngdhigddjfpcofhbmh). Установку самостоятельно подписанного CRX ограничивают правила браузера и корпоративные политики. Версия в магазине обновляется отдельно от GitHub.

Если браузер разрешает ручную установку CRX, скачайте пакет и контрольную сумму из одного релиза. Перед установкой сравните SHA-256 файла с опубликованной суммой.

### ZIP и ошибка CRX_REQUIRED_PROOF_MISSING

1. Скачайте runtime ZIP по ссылке выше и проверьте именно его SHA-256.
2. Распакуйте в постоянную папку.
3. Откройте `chrome://extensions`, включите «Режим разработчика» и нажмите «Загрузить распакованное расширение».
4. Выберите папку с `manifest.json`, а не сам ZIP.

`CRX_REQUIRED_PROOF_MISSING` относится к требуемому подтверждению CRX: самостоятельная подпись не гарантирует установку в обычном Chrome. Новый ключ `.pem` эту политику не заменяет. Для локальной проверки Google поддерживает [загрузку распакованного расширения](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked); обычный канал для пользователей Chrome — Web Store. Архив **Source code** этого репозитория содержит документацию, а не runtime. Папку распакованной установки нельзя удалять; автоматические обновления и перенос данных между разными ID не обещаются.

> [!TIP]
> Сохраняйте контрольную сумму рядом с CRX. При ручной смене канала установки могут отличаться ID расширения и локальные данные. Закрытый ключ `.pem` не входит в пакет и не нужен пользователям.

В 3.0.5 сохранены ключ подписи и ID ручной сборки 3.0.0 — `iahebdomfekhiofmdocjmdjpjlclnngd`. Он отличается от прежней ручной сборки с ID `kmebfblhgfacdonaomlggpkndcjjpkgd`: такой пакет не обновит её, а настройки и история автоматически не перенесутся. Перед сменой установки экспортируйте нужные данные через доступные действия расширения.

Версия 3.0.5 сохраняет возможности 3.0.2: JSON-копии статистики и истории, увеличенный кэш превью, поиск по длинной истории и прежние исправления inline-кнопок. Кодирование GIF остаётся в отдельном Worker; большие GIF требуют времени и ресурсов. Минифицированный JavaScript без source map остаётся доступен в DevTools. См. [изменения](CHANGELOG.md) и [локальные данные](docs/LOCAL_DATA.md).

## 🧩 Возможности

| Задача | Что доступно |
| --- | --- |
| Сохранить выбранное медиа | Поиск оригиналов изображений, прямые MP4/WebM и поддерживаемые GIF. Подписанные ссылки сохраняются целиком. |
| Скачать пост | Несколько файлов из постов X, Reddit, Pixiv, Pawchive и поддерживаемых страниц VK. Результат виден для каждого файла; оставшиеся можно отменить. |
| Выбрать папку | «Загрузки» браузера или явно выбранная папка. Уровни в выбранном порядке, свой шаблон и общая настройка имени папки для Booru. |
| Настроить новые имена | Исходное имя или выбранные поля: сайт, аккаунт, дата/время публикации в UTC. Составное имя не получает исходный CDN-хвост; неизвестные данные пропускаются. |
| Открыть сохранённое медиа | Изображения, анимированные GIF и MP4 с плеером; вписывание/100%, зум, перемещение, карусель с кнопками, клавиатурой и свайпом. |
| Следить за результатами | Popup, менеджер, уведомления на странице, статистика по желанию, повтор и отмена загрузки. Фильтры изображений/GIF и видео. |
| Скопировать ссылку для превью | 12 настроек: X, Instagram, TikTok, видео/Shorts YouTube, Reddit, Pixiv, Bluesky, Threads, Twitch, Tumblr и Bilibili. Преобразование ссылки выполняется локально. |
| Изменить интерфейс | Фиолетовая, красная, синяя, тёмная и светлая темы; русский/английский; управление клавиатурой и уменьшение анимации. |
| Посмотреть изменения | История версий доступна без интернета; установленная версия отмечена отдельно. |

Нажмите на миниатюру в менеджере, чтобы открыть просмотрщик. Из popup он открывается поверх активной вкладки, из уведомления — поверх исходной страницы. Просмотрщик работает в изолированном фрейме расширения. На системных страницах он открывается в менеджере. При наведении доступно маленькое превью.

В 3.0.5 локальный кэш содержит до 2 048 миниатюр и 256 оригиналов для превью: до 128 МиБ на оригинал, 512 МиБ суммарно и 30 дней доступности. Если файл не поместился или удалён из кэша, выберите его с диска. Кэш не заменяет резервную копию; скачанные файлы не меняются. Поддержка кодеков зависит от браузера.

### История и статистика

В разделе «Обзор → Локальные данные и резервные копии» можно отдельно сохранить статистику и историю в JSON. Восстановление статистики заменяет счётчики с подтверждением; импорт истории добавляет отсутствующие записи и не запускает скачивания. Ограничения: 32 МиБ UTF-8 на файл, до 50 000 записей в копии истории. Медиа, URL источников и права на папки в копию не входят. История показывается порциями, а поиск охватывает весь сохранённый список. [Подробнее](docs/LOCAL_DATA.md).

### Папки и имена

```text
Downloads/
└── SavedImages/
    ├── x/posting_account/Image/photo.jpg
    ├── reddit/posting_account/Videos/clip.mp4
    └── danbooru/uploader/Image/artwork.jpg
```

Выбирайте уровни папок в нужном порядке: сайт, аккаунт, тип медиа, расширение, дата, год–месяц или год. Доступен и свой шаблон; уровни с неизвестными данными пропускаются. Папки аккаунтов включаются отдельно для поддерживаемых сервисов. Для выбранных Danbooru/Moebooru можно использовать проверенного загрузившего пост; теги художников не считаются аккаунтом.

Поля даты и времени в имени файла используют подтверждённую дату публикации поста X или подходящие метаданные Danbooru/Moebooru в UTC. Если дата публикации неизвестна, эти поля пропускаются. Уровни папок «Дата», «Год–месяц» и «Год» используют дату публикации, а при её отсутствии — время начала операции в UTC. Настройки действуют на новые сохранения; уже скачанные файлы не переименовываются.

Для уровня `{type}` можно отдельно задать названия папок изображений, видео и GIF. Стандартные имена — `Image`, `Videos`, `GIF`; пустое поле возвращает стандартное имя. Меняется только уровень типа для новых сохранений: собственные имена, пути уже принятых заданий и существующие файлы сохраняются. Буквальный текст `Images` в шаблоне остаётся общей папкой, а не переключателем типа.

Если браузер снова запросил доступ к сохранённой папке, используйте «Восстановить доступ к папке» в настройках. Выбранная папка остаётся сохранённой. Для завершённых браузерных загрузок доступен показ файла в папке после проверки. У прямой записи в выбранную папку значок поясняет ограничение API открытия файлового менеджера; системная программа-помощник не нужна.

При совпадении имён расширение добавляет суффикс, даже после очистки истории и статистики. Существующие файлы не перезаписываются. Длинные имена могут сокращаться из-за ограничений пути. Слишком длинный путь Windows браузер или файловая система могут отклонить.

## 🌐 Как проходит сохранение

<p align="center"><img src="assets/readme/flow-ru.svg?v=violet-loop-2" width="1120" alt="Выбор медиа → проверка источника и файла → сохранение → локальное превью"></p>

Расширение ищет оригинал выбранного медиа, проверяет источник и файл, затем сохраняет его в папку. Файл из соседнего поста не используется как замена.

## 🌍 Поддержка сайтов

Наличие Copy на площадке не означает поддержку скачивания её медиа. VOD Twitch сохраняют исходный адрес; воспроизведение, звук и галереи зависят от выбранного зеркала и мессенджера. После обновления расширения перезагрузите уже открытые вкладки сайтов.

Результат зависит от выбранного медиа, вёрстки страницы и вашего доступа к источнику.

| Сайт или семейство | Что поддерживается |
| --- | --- |
| X / Twitter | Изображения и видео, преобразование поддерживаемых MP4-анимаций в GIF, загрузка нескольких файлов поста. |
| Reddit | Изображения, обычные GIF, прямые видео и ограниченный незашифрованный H.264/AAC HLS VOD. |
| Pixiv | Оригинал выбранной страницы иллюстрации или проверенный список её страниц; папки аккаунтов. |
| RedGIFs | Выбранные изображения и медиа плеера, включая поддерживаемое восстановление отдельного звука. |
| VK / VK Video | Фото, поддерживаемые карусели/коллажи/видео ленты, карточки-превью, открытые плееры и штатное скачивание клипов. Экспериментально; другие варианты страниц и звук требуют проверок. |
| TikTok / Instagram | Поддерживаемые выбранные видео/Reels и аккаунты публикации; источники только с раздельными дорожками могут быть недоступны. |
| Pawchive / Sankaku | Объявленные оригиналы выбранного поста; неполный импорт архива обозначается отдельно. |
| Booru | Выбранные оригиналы поддерживаемых движков с учётом авторизации и ограничений сайта. |
| Другие HTTP(S)-страницы | Атрибуты изображения, srcset, связанные метаданные и ссылки на его оригинал с проверкой принадлежности. Универсального поиска видео нет. |

DRM, эфиры, универсальная загрузка HLS/DASH, произвольное выделение галереи и скачивание YouTube не поддерживаются. Ошибки 403, истёкшие ссылки, отсутствующий оригинал и неподдерживаемый поток показываются как сбой. Соседний пост не используется как запасной источник.

## 🛡️ Приватность и безопасность

У MediaLatch нет собственного сервера и телеметрии. Скачивание обращается к выбранному источнику, сервису или CDN. Настройки, очередь, опциональная статистика, диагностика и превью хранятся в расширении. Ручная проверка версии обращается к GitHub и не устанавливает код.

Уведомления на странице показывают краткий результат загрузки. Содержимое оригиналов, права на папки и локальные пути остаются внутри расширения. Отчёт или диагностику можно экспортировать вручную; перед отправкой проверьте содержимое. Доступ HTTP/HTTPS нужен для поиска выбранного медиа на разных сайтах. Подробнее: [политика приватности и разрешения](docs/PRIVACY.md).

О багах, проблемах и уязвимостях сообщайте на [always1337@vk.com](mailto:always1337@vk.com) или в [Issues](https://github.com/xhthc/MediaLatch/issues). Подробности уязвимостей и чувствительные данные отправляйте на почту. Что приложить к сообщению и как проводить проверку, описано в [Security Policy](SECURITY.md).
